# OCR 엔진 구조화 결과 비교

## 1. 평가 목적

개인정보가 없는 합성 처방전을 대상으로 CLOVA OCR, PaddleOCR, RapidOCR의 구조화 결과를 비교한다.

이번 평가는 OCR 모델의 글자 인식 성능을 고도화하는 것이 아니라, 각 OCR 결과가 처방일자와 약품별 복용 정보로 얼마나 정확하게 구조화되는지 확인하는 데 목적이 있다.

구김·기울기·얼룩 등으로 원문 글자 자체를 인식하지 못하는 문제는 OCR 엔진의 인식 영역으로 구분하고, 이번 평가에서는 인식된 텍스트를 약품 행과 필드로 변환하는 과정에서 발생하는 누락·오탐·잘못된 행 연결을 중심으로 분석한다.

이번 작업에서 운영 OCR 엔진은 교체하지 않는다.

## 3. 엔진 및 실행 조건

### CLOVA OCR

- 엔진: NAVER Cloud CLOVA OCR General API V2
- 실행 방식: 기존 Backend OCR API 및 구조화 로직 사용
- 구조화 방식: CLOVA 좌표 기반 처방일자·약품 행 구조화
- 운영 연동 상태: 현재 Backend에 실제 연동됨
- 모델 버전: 외부 서비스에서 별도로 노출하지 않음

### PaddleOCR

- 라이브러리 버전: 3.3.0
- 검출 모델: `PP-OCRv5_server_det`
- 인식 모델: `korean_PP-OCRv5_mobile_rec`
- 실행 환경: macOS CPU
- 문서 방향 보정: 사용하지 않음
- 문서 왜곡 보정: 사용하지 않음
- 텍스트 줄 방향 보정: 사용하지 않음
- 운영 연동 상태: 독립 평가 스크립트로만 실행

### RapidOCR

- 라이브러리 버전: 3.9.2
- 실행 Runtime: ONNX Runtime 1.29.0
- 검출 모델: `ch_PP-OCRv5_det_mobile`
- 방향 분류 모델: `ch_ppocr_mobile_v2.0_cls_mobile`
- 인식 모델: `korean_PP-OCRv5_rec_mobile`
- 실행 환경: macOS CPU
- 운영 연동 상태: 독립 평가 스크립트로만 실행

PaddleOCR와 RapidOCR는 서로 다른 크기의 검출 모델을 사용한다. 따라서 결과를 라이브러리 자체의 절대적인 성능 순위로 해석하지 않는다.

## 4. 평가 기준

정답은 생성 프롬프트나 실제 의약품 표준 명칭이 아니라 최종 이미지에 표시된 문자열을 기준으로 작성했다.

### 정답 필드 수

```text
정답 필드 수 = 1 + 약품 수 × 6
```

### 재현율

```text
재현율 = 일치 필드 / 정답 필드 × 100
```

### 정밀도

```text
정밀도 = 일치 필드 / (일치 필드 + 오탐 필드) × 100
```

### 약품 행 완전 일치율

```text
약품 행 완전 일치율
= 6개 필드가 모두 일치한 약품 행 / 전체 정답 약품 행 × 100
```

### 정규화 규칙

- 약품명과 복용 시점의 공백 차이는 제거한 후 비교한다.
- 가운데점 주변의 공백 차이는 같은 값으로 처리한다.
- 날짜의 `.`, `/`, `-` 구분자 차이는 같은 날짜로 처리한다.
- 잘못 반환된 값은 정답 기준 불일치 1건이면서 출력 기준 오탐 1건으로 계산한다.
- 실제 약품 수보다 추가로 생성된 행의 값은 오탐으로 계산한다.

### 결과 해석

- PaddleOCR는 필드 단위 재현율과 정밀도가 가장 높았다.

- PaddleOCR는 일부 필드 누락이 여러 약품 행에 분산되어 있어 필드 단위 성능에 비해 행 전체 완전 일치율이 낮았다.
- RapidOCR는 오탐 수가 적어 정밀도는 높지만 누락이 많아 재현율과 약품 행 완전 일치율이 낮았다.
- 세 엔진에는 서로 다른 모델과 구조화 로직이 적용됐으므로 이 결과만으로 OCR 엔진의 순수 인식 성능을 단정할 수 없다.

## 7. PNG·JPG 비교

동일한 clean 처방전을 PNG와 JPG 품질 90으로 비교했다.

| 엔진 | PNG 재현율 | JPG 재현율 | PNG 정밀도 | JPG 정밀도 |
|---|---:|---:|---:|---:|
| CLOVA OCR | 92.3% | 92.3% | 75.0% | 75.0% |
| PaddleOCR | 92.3% | 92.3% | 100.0% | 100.0% |
| RapidOCR | 76.9% | 61.5% | 100.0% | 100.0% |

### 분석

- CLOVA OCR와 PaddleOCR는 PNG와 JPG의 최종 구조화 정확도가 같았다.
- PaddleOCR는 JPG에서 약품명 열 제목 `명칭`을 `명청`으로 인식했지만, 구조화기의 제목 판정 조건을 보완한 후 정상적으로 처리됐다.
- RapidOCR는 JPG에서 첫 번째 약품의 `1정`을 추가로 누락해 재현율이 15.4%p 감소했다.
- 이번 한 건의 결과만으로 일반적인 확장자 성능을 단정하지 않고 참고 사례로만 사용한다.

## 8. 주요 구조화 실패 유형

### 8.1 복약 안내 문장을 약품 행으로 분류

CLOVA OCR에서 약품 표 아래의 복약 안내 문장을 추가 약품으로 분류하는 오탐이 반복됐다.

대표 사례:

- `1.`
- `2. 약을`
- `즉시`
- `복약 안내 3. 가벼운`
- `4. 다른 약을`

이 문제는 글자 인식 오류보다 약품 표의 종료 경계와 유효한 약품 행 판정 문제에 가깝다.

### 8.2 실제 약품 행 누락

- 약품명은 인식했지만 기간이나 용량 일부가 누락됐다.
- 다약제 이미지에서 약품 행 전체 또는 약품명이 누락됐다.
- RapidOCR는 손상 이미지에서 필수 열 제목을 찾지 못해 구조화 전체가 중단됐다.

### 8.3 잘못된 열 연결

약품명에 포함된 숫자가 1일 횟수로 연결되거나, 기울어진 이미지에서 다른 열의 문자열이 약품 정보로 들어가는 사례가 발생했다.

대표 사례:

- 약품명의 `10mg`이 `FREQUENCY_PER_DAY=10`으로 연결
- 조제 영역의 `조제자`가 복용 시점으로 연결
- 복약 안내의 숫자가 횟수로 연결

### 8.4 필수 열 제목 의존

PaddleOCR와 RapidOCR 평가용 구조화기는 필수 열 제목을 기준으로 컬럼 위치를 계산한다.

JPG에서 `처방의약품명칭`이 `처방의약품명청`으로 인식되자 구조화가 중단됐으며, 제목 접두어를 허용하도록 보완한 후 정상 처리됐다.

특정 열 제목 하나를 찾지 못했을 때 전체 결과를 비우는 방식보다 확인된 열 위치를 이용해 나머지 컬럼을 추정하는 방식이 필요하다.

## 9. 엔진별 장단점

### CLOVA OCR

장점:

- 현재 Backend에 실제 연동되어 있다.
- 별도 모델 설치와 실행 환경 구성이 필요하지 않다.
- clean·long_name·damaged 이미지에서 비교적 높은 재현율을 보였다.
- 세 엔진 중 약품 행 완전 일치율이 가장 높았다.

고려사항:

- 복약 안내를 약품 행으로 분류하는 오탐이 반복됐다.
- 기울어진 이미지에서 좌표 기반 구조화 성능이 크게 저하됐다.
- 외부 서비스 연결, 인증정보, 장애 및 비용을 고려해야 한다.
- 원문 OCR과 좌표가 현재 Backend 조회 응답에 모두 노출되지는 않는다.

### PaddleOCR

장점:

- 전체 필드 재현율과 정밀도가 가장 높았다.
- 손상 및 기울기 이미지의 구조화 결과가 비교적 안정적이었다.
- 로컬 실행이 가능해 외부 OCR 호출 비용이 없다.

고려사항:

- 서버용 검출 모델을 CPU에서 실행해 모델 준비와 OCR 처리에 시간이 오래 걸린다.
- 모델과 라이브러리 설치 용량 및 실행 환경 관리가 필요하다.
- 필드 정확도에 비해 약품 행 전체 완전 일치율은 낮았다.
- 현재 운영 서비스와 Worker에는 연결되어 있지 않다.

### RapidOCR

장점:

- ONNX Runtime 기반으로 실행이 빠르고 구성도 비교적 가볍다.
- 오탐 수가 적어 정밀도는 비교적 높았다.
- 엔진·Runtime·모델 정보와 처리시간을 결과에 기록할 수 있다.

고려사항:

- 필드 누락이 많아 전체 재현율이 낮았다.
- 손상 이미지에서는 구조화 결과를 생성하지 못했다.
- JPG에서 용량 필드가 추가로 누락됐다.
- 현재 결과만으로는 처방전 구조화의 주 엔진으로 사용하기 어렵다.

## 10. MVP 판단

### 현재 MVP를 막는 문제

다음 조건은 사용자 확인·수정 흐름을 방해할 수 있으므로 우선 확인이 필요하다.

- 복약 안내 문장을 약품으로 생성한 추가 행을 사용자가 제거할 수 없는 경우
- 필수 필드가 누락된 행을 확인·수정할 수 없는 경우
- 약품 행 순서가 화면과 Backend에서 다르게 반환되는 경우
- 구조화 실패가 발생했는데 완료 상태만 반환하여 사용자가 실패를 알 수 없는 경우

사용자가 잘못된 값과 추가 행을 모두 확인·수정할 수 있다면 현재 구조화 결과는 MVP의 검토 기반 흐름에서 사용할 수 있다.

### 후속 개선 항목

- 약품 표 종료 경계 판정
- 유효한 약품 행 조건 강화
- 복약 안내·조제 영역 제외
- 열 제목 OCR 오차 허용
- 확인된 열을 이용한 누락 열 위치 추정
- 약품 필드 반환 순서 정렬
- 구조화 실패 사유 기록
- 다양한 실제 양식에 대한 구조화 규칙 확장
- 기울기·구김·얼룩 등 OCR 인식 자체의 고도화
- confidence 임계값 및 보정
- PaddleOCR·RapidOCR 서비스 연동
- PDF 비교

## 11. 결론

이번 평가에서는 PaddleOCR가 필드 단위 재현율과 정밀도에서 가장 높은 결과를 보였다. CLOVA OCR는 필드 단위 지표는 낮았지만 약품 행 완전 일치율이 가장 높았고 현재 Backend에 실제 연동되어 있다.

RapidOCR는 실행이 빠르고 오탐이 적지만 누락이 많아 현재 구조화 기준으로는 주 엔진으로 사용하기 어렵다.

다만 세 엔진에 서로 다른 모델과 구조화 로직이 적용됐기 때문에 이번 결과를 OCR 엔진 자체의 절대적인 성능 순위로 해석하지 않는다.

이번 이슈에서는 운영 OCR 엔진을 교체하지 않고 현재 CLOVA OCR 연동을 유지한다. PaddleOCR와 RapidOCR 결과는 구조화 실패 유형과 개선 방향을 확인하기 위한 비교 자료로 사용한다.

향후 개선의 우선순위는 OCR 모델 변경이 아니라 다음과 같은 구조화 안정성 향상이다.

1. 약품 표 종료 경계 판정
2. 복약 안내 문장의 약품 행 오분류 방지
3. 유효한 약품 행 판정 조건 강화
4. 열 제목 일부 누락 시 전체 구조화 중단 방지
5. 사용자 확인·수정 화면에서 누락·추가 행 처리 가능 여부 확인

---

## 12. 평가 제한

- 개인정보가 없는 AI 생성 합성 처방전 5건을 사용했다.
- 실제 환자 처방전을 사용하지 않았다.
- 평가 이미지 수가 적어 통계적인 일반화에는 한계가 있다.
- 엔진마다 사용 모델과 구조화 로직이 다르다.
- PaddleOCR와 RapidOCR는 운영 환경이 아닌 macOS CPU에서 실행했다.
- 처리시간과 배포 성능은 최종 엔진 선택 지표에서 제외했다.
- PDF는 이번 평가에 포함하지 않았다.
- 결과는 현재 평가 데이터와 구조화 코드 기준의 비교다.
