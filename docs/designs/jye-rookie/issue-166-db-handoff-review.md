## 다음 구현으로 넘어가는 조건

1. D-02 실행/Publication 의미와 물리 연결이 인계되고 구현 소유가 정해졌다.
2. 이번 v2 저장에 필요한 D-03~D-06 범위와 기존 데이터 처리 방안이 검토됐다.
3. 선행 Evidence/Citation migration과 최신 공통 head를 확인했다.
4. 위 결과를 Proposed 문서와 migration 설계에 반영했다.

이 문서 작성으로 완료한 것은 **DB 인계·결정 검토안 준비**다. 결정 합의, migration 구현 또는
#166 전체 완료가 아니다. 새 projection/Runtime hash 전환은 이번 v2 저장 구현에 임의로 포함하지 않는다. Crosswalk 필수 범위는
검토 결과로 완료 조건에 반영한다. 남은 범위를 정리하지 않고 v2 DB 통합 PR 병합만으로 #166을 자동 종료하지 않는다.

## 공유용 검토 요청 초안

### 은영님께

은영님, #166 DB 연결안을 정리했습니다. D-02는 말씀 나눈 대로 미확정으로 유지했습니다.
#165 실행 생성·재시도와 #166 적재안은 제가 제안·구현하고, 공유 DB 참조를 맞추는 부분을 같이 보고 싶습니다.

특히 아래 세 부분 검토 부탁드립니다.

- 같은 Snapshot의 Catalog 재처리를 구분할 실행/Publication 참조와 기존 Snapshot의 연결 방식
- Identity·Alias/Set·현재 v2 hash 계산 자료의 저장 위치, FK·불변성 및 기존 행 이행안
- adapter의 transaction 소유, 승인/Source 변경과의 경합 제어, 실패 감사 저장 위치

기존 구조로 가능한 부분과 공유 구조 변경이 필요한 부분을 짚어주시면 그에 맞춰 migration을 구체화하겠습니다.
Evidence/Citation 선행 revision은 준비되는 대로 연결해 주시면, 제 migration 착수 전에 최신 head와 대조하겠습니다.

### 현우님께

현우님, #166 후속 DB 검토안을 정리했습니다. D-02는 미확정이고, 별도 run 생성이나 ingestion run 대체는 하지 않았습니다.
현재 v2 envelope hash와 CatalogExportArtifacts 인계도 유지합니다.

같은 Snapshot의 다른 Catalog 처리와 같은 요청의 재시도를 구분하는 안, 관찰 Alias 집합과 검색 적격 집합의
분리, Crosswalk의 이번 P0 필수 범위를 봐주시면 좋겠습니다. Component는 실제 Source 근거 전까지 role을
포함한 자연키를 유지하는 안이며, 승인 철회·Source 변경·재시도 때 기존 결과를 어떻게 보존하고 소비를
차단할지도 검증 사례로 정리했습니다. 의미가 어긋난 부분은 이 단계에서 반영하겠습니다.
