# #458 OCR LLM 동의·전송 후속 계약

- 상태: Proposed — Worker 검사·차단 저장 로컬 구현. Backend/Frontend 연계·최소화·최종 문구/버전·리뷰 미완료.
- 확인일: 2026-09-14. 최신 답변 근거와 저장 결정은
  [#458 Worker 결정안](../../governance/decisions/2026-09-14-ocr-consent-worker-458.md)에 연결한다.
- 구현: 김지혜. Privacy/Product: 권가빈. Backend/Security: 송은영. Frontend/UX: 남한솔.
- 관련: #458, #453/PR #454, #207/PR #465. #166과 기능 의존성 없음.

## 확인된 방향

1. 기존 `OCR` 목적에 외부 OCR 인식과 외부 LLM 구조화를 함께 명시한다. 기존 안내가 외부
   OCR만 포함했다면 과거 동의를 LLM으로 자동 확대하지 않는다. 변경 안내·policy version
   확정 및 해당 안내에 재동의한 이후 LLM 처리를 이용한다. 최종 문구·버전 값은 아직 미확정이다.
2. 원본 이미지·OCR 전체 텍스트를 LLM에 보내지 않는다. OCR이 인식한 약품·복용 정보 중 필요한
   항목만 보낸다. 처방일·위치·높이·confidence는 필요성을 확인한 항목만 포함한다.
   안전하게 범위를 구분하지 못하면 LLM 호출을 생략한다. 구체 허용 항목·차단 기준은 기술 검토 대상이다.
3. 미동의·철회로 외부 처리가 차단되는 경우와 동의는 유효하지만 최소화 조건 미충족으로 LLM을
   생략하는 경우를 구분한다. 철회를 정상 처리 성공으로 표시하지 않는다.
4. 철회 후 이미 얻은 OCR 결과의 검수 허용 여부는 보관·삭제 정책 확인 후 확정한다.
   그전에는 검수 허용을 전제로 구현하지 않으며 직접 입력 경로는 유지한다.
   이는 기존 자료 삭제 지시나 OCR 값을 직접 입력 값으로 자동 복사해도 된다는 결정이 아니다.
5. 동의 확인·철회 차단·전송 최소화·Frontend 안내가 연결되고 검증된 뒤에만 실제 사용자 대상
   LLM 활성화를 검토한다. 기존 Privacy Production·관련 외부 승인 게이트도 충족해야 한다.
   합성 데이터 검증은 실제 활성화와 구분한다.

## Frontend 확인 기록 — 2026-09-13

사용자 전달 남한솔 Discord 19:32 및 MD 검토 후 19:37 답변 기준이다. 공개 원문 링크는
미연결이며, 아래는 UX 방향 확인이지 신규 API 필드·enum·HTTP 상태 승인이나 구현 완료가 아니다.

- 기존 목적별 동의 UI·설정·이력 흐름을 재사용한다. 회원가입 필수 동의로 올리지 않는다.
- 안내 위치는 화면 이름이 아니라 **최초 외부 전송 직전**을 기준으로 정한다. 업로드/처리 시작과
  외부 호출이 이어진다면 그 흐름 시작 전에 유효한 OCR policy 동의를 확인한다.
- 최신 정책의 유효 동의가 있으면 반복 팝업 없이 진행한다. 미동의·철회·이전 정책이면 안내한다.
- 처리 중 철회를 일반 실패나 정상 LLM 생략과 동일하게 표시하지 않는다.
- `llm_processing`이 없거나 null이면 LLM 사용 여부를 추정하지 않는다.
  `STALE`만으로 철회라고 판단하지 않고 확정된 사유 계약을 함께 확인한다.
- 기존 `manual-medications`는 OCR COMPLETED에서만 가능하므로 독립 직접 입력 저장 경로를
  Backend에서 확인하기 전에는 미동의·철회 화면과 기존 API의 연결 가능성을 가정하지 않는다.
- 안내 문구는 화면 초안에 사용 가능하나 최종 문구·policy version은 가빈 확인 후 확정한다.
- 한솔은 화면 구조와 기존 UI 재사용 검토를 먼저 진행할 수 있다. 실제 연동은 은영과 확정된
  DTO/OpenAPI를 받은 뒤 진행하며, 그때 변경 범위와 일정을 공유한다.

지혜는 Worker/OCR과 연계 요구·계약 초안을 담당한다. Backend API·동의 저장·철회·감사
구현 담당 및 변경 범위는 은영과 조율하며 지혜가 Backend 전체를 맡는 것으로 간주하지 않는다.

## 기술 경계 제안 — 은영 확인 대상

- 기존 #207 Backend 접수 전·Worker CLOVA 호출 전 검사와 연결하며, CLOVA 완료 후 LLM 호출
  직전 최신 동의를 재검사한다. enqueue 시점 동의 상태를 그대로 재사용하지 않는다.
- 주체·목적·현재 policy·철회·조회 실패 검증은 애플리케이션 Service/Repository에서 처리한다.
  유효한 동의를 확인할 수 없으면 외부 호출하지 않는다. Worker 메시지에 동의 상태·건강정보를
  추가하지 않고 Backend ORM을 Worker로 import하지 않는다.
- #207 저장소를 재사용한다. 저장 기반 연결을 동의 수집·철회 API/UX 연결 완료로 표시하지 않는다.
- 전송 허용 token과 원래 OCR source ID의 결속을 유지하며 전송하지 않은 token 참조는 거부한다.
  단순 재번호화로 grounding 의미를 바꾸지 않는다. 출력 금지 프롬프트나 일부 정규식 마스킹을
  개인정보 비전송 보장으로 취급하지 않는다.
- 재검사 이후 실제 전송 시작 사이의 경합, 진행 중 외부 호출, 철회 시 상태·오류 저장·재시도
  경계를 확인한다. 이미 전송된 요청을 회수할 수 있다고 주장하지 않는다.

## 사용자 흐름·Frontend 인계

| 상황 | 기준 | 남은 확인 |
| --- | --- | --- |
| 과거 OCR 전용 동의 | LLM 전송 근거로 자동 재사용 금지 | 최종 고지·버전·재동의 UX, 기존 OCR 이용 범위 |
| 미동의·철회 | 외부 처리 차단, 성공 표시 금지 | #207 상태·오류 연결 및 안내 |
| 유효 동의·최소화 실패 | LLM 생략, 철회와 구분 | 규칙 기반 결과의 표시 상태·안내 |
| 철회 후 기존 OCR 결과 | 검수 허용 전제로 구현하지 않음 | 가빈의 보관·삭제 정책 확인 |
| 직접 입력 | 경로 유지 | 한솔의 화면·상태 연결 |

Frontend 코드는 김지혜 작업에서 대신 변경하지 않는다. 외부 OCR 이미지 처리와 LLM 텍스트
처리를 구분한 안내, 재동의·설정 이동 및 위 상태의 화면을 남한솔과 확정한다.
사용자의 인식 결과 검수는 전송 동의를 대신하지 않는다.

## 검증·완료 조건

허용 필드·차단 기준이 확정되면 원본/전체 token 비전송, 개인정보 sentinel 비전송,
미동의·철회·조회 실패 시 LLM 호출 0건, 허용 token grounding, 기존 직접 입력 흐름을 검증한다.
은영의 기술 검토, 가빈의 최종 정책, 한솔의 안내·사용자 흐름 및 실제 저장소 통합이 남아 있다.
RLS·DB Trigger·업무용 DB 함수 없이 명시적 Python 검증·transaction과 일반 제약·최소 권한을 사용한다.

#453의 “활성화 신규 선행조건으로 두지 않는다”는 당시 PR 범위 기록이다. #458에서 위 후속
방향이 확인됐으며 과거 문장으로 실제 사용자 전송 조건을 우회하지 않는다. 최종 계약·구현이
완료될 때 관련 문서 상태를 함께 정렬한다. 이 문서는 환경 활성화·배포·외부 전송을 승인하지 않는다.


## 2026-09-14 Backend·PM 답변 및 로컬 구현

[동의 조회·재검사 구현 기록](../../designs/ocr-consent-gate-458-implementation.md) 및
[Worker 차단 저장 결정안](../../governance/decisions/2026-09-14-ocr-consent-worker-458.md)에
원문 링크와 구체 사유·상태·재시도·ACK 순서를 기록한다. #465는 develop에 병합됐다.
Backend는 접수 전, Worker는 CLOVA 직전·LLM 직전 및 결과 성공 반환 전 검사를 담당한다.
동의 API/Frontend 및 전송 최소화는 아직 미완료다. 새 공유 FailureCode나 DB 스키마는 추가하지 않는다.

가빈 답변에 따라 철회 후 기존 OCR 결과 재노출·검수·수정은 데모에서 제외한다. 보관·삭제는
실제 사용자 적용 전 별도 결정이며 보관 허용으로 해석하지 않는다. 완전 수동 입력은 OCR Job 없이
처방일·처방약을 입력·확정하는 독립 경로다. 새 구현은 별도 후속으로 분리할 수 있으며 #458/데모
필수조건으로 두지 않는다. 유효 동의·LLM 최소화 생략이면 기존 OCR 검수·수정을 재사용한다.
