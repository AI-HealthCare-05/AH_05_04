## 먼저 결정할 제품 방향

복용을 놓친 원인이나 약 부작용을 진단하지 않는다. 사용자가 선택한 안전 신호에 따라
도움 요청을 먼저 안내하고, 증상 없음이 명시적으로 확인된 경우에만 Barrier로 진행한다.
NHS의 문장을 앱 코드에 연결한 아래 표는 팀의 제안이며 NHS가 이 앱을 검증했다는 뜻이 아니다.
이 문서 작성 요청을 제품·의료 승인으로 기록하지 않는다.

권장 데모 범위는 국내 성인 SELF 사용자에 대한 합성 시나리오다. 성인 한정은 아직
확정된 제품 계약이나 구현된 연령 제한이 아니다. 아동·보호자·해외 사용까지 검증했다고
주장하지 않으며, 실제 대상 범위 및 필요한 코드상 제한은 적용 전에 확정한다.

## 1. 화면에서 묻는 질문

제목: **“지원 안내 전에 증상을 확인할게요”**

설명: “해당하는 항목을 모두 선택해 주세요. 이 확인만으로 질환이나 약의 부작용을 판단할 수는 없어요.”

- 기본 질문은 현재 증상이다. 최근 24시간 질문은 아래 신경학적 신호에만 적용한다.
- “목록에 없는 다른 증상이 있어요”와 “증상이 있는지 잘 모르겠어요”를 제공한다. 자유 입력은 받지 않는다.
- “현재 증상이 없고, 최근 24시간 동안 아래 얼굴·팔·말하기 변화도 없었어요”를 별도 단독 선택으로 둔다.
- 선택 없음은 미응답이다. 자동으로 `[]`를 제출하지 않는다. 증상 없음과 다른 항목의 동시 선택은 막는다.
- 이미 선택한 증상을 조용히 지우지 않는다. 증상 없음으로 바꿀 때 기존 선택 해제를 알리고 명시적으로 확인받는다.
- 119 도움 요청은 항상 접근 가능하게 둔다. 응급 항목 선택 시 안내를 즉시 보여주며,
  저장 성공·로그인 재시도·모든 질문 응답 완료를 기다리게 하지 않는다. 자동 전화 발신은 하지 않는다.
  이는 선택 항목에 연결된 고정 도움 안내이며 Frontend가 자체 severity를 계산·저장하는 것은 아니다.

최근 24시간 신호를 추가하는 것은 기존 “현재 증상 없음” 표현보다 넓은 입력 의미다.
따라서 이 부분은 명시적인 계약 delta로 검토하며, 기존 DTO의 `[]`가 이를 확인했다고 소급 해석하지 않는다.

## 2. 증상 선택표

코드는 모두 앱용 후보이며 NHS 공식 코드가 아니다. `갑자기`, `지속`, `가슴 통증과 함께`,
`최근 24시간` 같은 조건은 화면·코드·테스트에서 보존한다. 표의 번호는 화면 정렬용이며 API 값이 아니다.

### 응급 도움 우선 후보 — EMERGENCY

| 번호 | 제안 symptom_code | 사용자 선택 문구 초안 | 근거 |
|---|---|---|---|
| E01 | `SUDDEN_AIRWAY_SWELLING` | 입술·입안·혀·목이 갑자기 부었어요 | S1 |
| E02 | `SEVERE_BREATHING_DIFFICULTY` | 숨쉬기가 힘들거나 숨을 매우 빠르게 쉬고 있어요 | S1 |
| E03 | `THROAT_TIGHTNESS_OR_SWALLOWING_DIFFICULTY` | 목이 조이는 느낌이 들거나 삼키기가 어려워요 | S1 |
| E04 | `BLUE_GREY_OR_PALE_SKIN_LIPS_TONGUE` | 피부·입술·혀가 파랗거나 회색빛 또는 창백하게 변했어요 | S1 |
| E05 | `SUDDEN_CONFUSION_DROWSINESS_OR_DIZZINESS` | 갑자기 정신이 혼란스럽거나, 졸리거나, 어지러워졌어요 | S1 |
| E06 | `SUDDEN_PERSISTENT_CHEST_PAIN` | 갑자기 생긴 가슴 통증이나 불편감이 계속돼요 | S2 |
| E07 | `CHEST_PAIN_SPREADING` | 가슴 통증이 팔·목·턱·배·등으로 퍼져요 | S2 |
| E08 | `CHEST_PAIN_WITH_ASSOCIATED_SYMPTOMS` | 가슴 통증과 함께 식은땀·메스꺼움·어지러움·숨참 중 하나 이상이 있어요 | S2 |
| E09 | `CURRENT_OR_RECENT_FACE_WEAKNESS` | 갑자기 얼굴 한쪽이 처지거나 웃기 어려워졌어요. 지금 증상이 있거나 최근 24시간 안에 있었다면 선택해 주세요 | S3 |
| E10 | `CURRENT_OR_RECENT_ARM_WEAKNESS` | 갑자기 한쪽 팔의 힘이 빠지거나 감각이 둔해져 양팔을 들고 있기 어려워졌어요. 지금 증상이 있거나 최근 24시간 안에 있었다면 선택해 주세요 | S3 |
| E11 | `CURRENT_OR_RECENT_SPEECH_CHANGE` | 갑자기 말이 어눌해지거나 말하기 어려워졌어요. 지금 증상이 있거나 최근 24시간 안에 있었다면 선택해 주세요 | S3 |

E04는 피부색에 따른 식별 차이를 검토한다. E05는 평소 피로·오래된 어지러움까지
동일하게 분류하지 않도록 `갑자기` 조건과 이해도를 검토한다. 서버가 발병 시점·중증도를 추정하지 않는다.

S1의 “실신 후 깨울 수 없음”은 본인 SELF 화면에서 직접 응답할 수 있는 상태가 아니다.
이를 선택지 하나로 해결했다고 주장하지 않는다. 본인이 응답할 수 없는 상황은 설문 이용 대상이 아니며
주변인이 즉시 도움을 요청해야 한다는 경계를 안내한다. 아동의 반응 저하 항목도 이 초안 범위 밖이다.
S3의 FAST 외 징후도 존재하므로 E09~E11을 전체 뇌졸중 배제 검사로 설명하지 않는다.

### 신속한 진료 후보와 미분류 입력

| 번호 | 제안 symptom_code | 사용자 선택 문구 초안 | 결과 후보 / 근거 |
|---|---|---|---|
| U01 | `SUDDEN_OTHER_BODY_SWELLING` | 손·발 등 다른 신체 부위가 갑자기 부었어요 | URGENT / S1. 응급 항목 동반 시 EMERGENCY 우선 |
| X01 | `OTHER_SYMPTOM` | 목록에 없는 다른 증상이 있어요 | UNKNOWN / 앱의 판단 범위 제한 |
| X02 | `UNSURE_ABOUT_SYMPTOMS` | 증상이 있는지 잘 모르겠어요 | UNKNOWN / 앱의 판단 범위 제한 |
| N01 | 코드 없음, 명시적 확인 후 `[]` | 현재 증상이 없고, 최근 24시간 동안 위 얼굴·팔·말하기 변화도 없었어요 | ROUTINE / 기존 빈 목록 계약 + 시점 의미 확장 제안 |

두통·발진·메스꺼움 등 일반 증상 전체를 정상으로 분류하지 않는다. 이 초안에 구체적인
판정 근거를 연결하지 않은 항목은 X01로 남긴다. UNKNOWN은 낮은 위험도라는 뜻이 아니다.

## 3. 서버 판정 규칙 제안

유효한 구조화 목록에 다음 순서로 적용한다. 이 순서는 NHS가 제공한 알고리즘이 아니라
선택된 응급 신호를 낮추지 않기 위한 앱 정책 제안이다.

1. E01~E11 중 하나라도 있으면 `EMERGENCY / EMERGENCY_ROUTED`.
2. 응급 항목 없이 U01이 있으면 `URGENT / URGENT_ROUTED`.
3. 나머지 비어 있지 않은 목록(X01·X02·미등록 코드)은 `UNKNOWN / UNKNOWN_RISK`.
4. 명시적 증상 없음 확인으로 제출한 빈 목록만 `ROUTINE / NORMAL`.

- U01 + X01/X02/미등록 코드도 URGENT 안내는 유지하지만, 다른 증상이 안전하다고 판단하지 않는다.
  URGENT 고정 문구에 판단 한계를 포함한다. UNKNOWN을 단순 숫자 severity로 비교하지 않는다.
- EMERGENCY에 UNKNOWN이 섞여도 응급 안내가 사라지면 안 된다.
- 모든 non-ROUTINE은 Barrier·일반 Support를 차단한다. 기존 저장·정정·멱등 처리 계약은 유지한다.
- `[]` 요청만으로 서버가 실제 UI 확인 행위를 증명할 수는 없다. 현 계약은 명시적 제출을 신뢰한다.
  확인 증빙 필드가 필요하면 별도 DTO 변경으로 검토한다.
- 형식 위반은 기존 422 처리이며, 에러 자체를 ROUTINE으로 변환하지 않는다. 네트워크·저장 실패도 동일하다.
- LLM, 점수 모델, 약물별 인과관계 추정, 약 중단·용량·복용 시간 변경은 사용하지 않는다.

## 4. 한국어 안내 정본 초안

다음 문구는 NHS 원문 직접 인용이 아니라 국내 화면을 위한 작성 초안이다.
긴급도 용어만 보여주지 말고 다음 행동을 함께 표시한다. 아래 CTA는 화면 제안이며
현재 Safety 응답 DTO에 새 필드를 추가한 것이 아니다.

| message_code 후보 | 제목 | 본문 | 주 행동 / 보조 행동 |
|---|---|---|---|
| `SAFETY_EMERGENCY_HELP` | 지금 응급 도움을 요청해 주세요 | 선택하신 증상은 즉시 응급 도움이 필요할 수 있어요. 지금 119에 연락해 주세요. 직접 운전하지 말고, 가능하면 주변 사람에게 도움을 요청해 주세요. | 119 전화 연결 / 선택 내용 다시 확인 |
| `SAFETY_URGENT_CARE` | 지금 진료 안내를 받아 주세요 | 선택하신 증상은 신속한 진료가 필요할 수 있어요. 지금 의료기관에 연락해 진료 안내를 받아 주세요. 이 확인만으로 다른 증상의 긴급도까지 판단할 수는 없어요. 숨쉬기 어려움이나 갑작스러운 입·혀·목 부종이 있으면 바로 119에 연락해 주세요. | 선택 내용 다시 확인 / 119 전화 연결 |
| `SAFETY_UNCERTAIN` | 증상을 더 확인할 필요가 있어요 | 입력하신 정보만으로 긴급도를 판단하기 어려워요. 의료진에게 증상을 확인해 주세요. 숨쉬기 어려움이나 갑작스러운 입·혀·목 부종 등 응급 신호가 있으면 바로 119에 연락해 주세요. | 선택 내용 다시 확인 / 119 전화 연결 |
| `SAFETY_NO_SYMPTOMS_CONFIRMED` | 증상 없음으로 확인하셨어요 | 확인 항목에 해당하는 증상이 없다고 응답하셨어요. 복용하지 못한 상황을 함께 확인할게요. | 복용하지 못한 상황 확인 / 선택 내용 다시 확인 |

공통 한계 문구: “이 확인은 진단이 아니며, 약 복용 여부나 용량을 결정해 주지 않아요.”

저장 실패 문구: “확인 내용을 저장하지 못했어요. 응급 도움이 필요하면 저장을 기다리지 말고
119에 연락해 주세요.” 실패 상태에서는 Barrier 진행 버튼을 활성화하지 않는다.

ROUTINE에 “안전해요”, “부작용이 없어요”, “약을 드셔도 돼요”를 표시하지 않는다.
URGENT의 진료 안내 버튼을 제공하려면 실제 목적지를 먼저 정한다. 존재하지 않는 예약·기관 검색 기능을
약속하지 않는다. 전화 CTA는 사용자가 누를 때 전화 앱을 여는 제안(`tel:119`)이며,
전화 기능이 없는 기기에서도 번호와 도움 요청 문구를 읽을 수 있어야 한다.

## 5. 출처와 버전

확인일은 모두 2026-09-15다. NHS 임상 설명과 국내 연락 경로를 구분한다.

| ID | 원문과 위치 | 원문 표시 검토일 / 다음 검토일 | 사용 범위 |
|---|---|---|---|
| S1 | [NHS Angioedema](https://www.nhs.uk/conditions/angioedema/) · When and where to get medical help | 2026-08-25 / 2029-08-25 | 급성 부종·호흡 등 응급 신호, 기타 부위 부종의 긴급 진료, 직접 운전 금지 |
| S2 | [NHS Chest pain](https://www.nhs.uk/symptoms/chest-pain/) · Immediate action required | 2023-08-08 / 2026-08-08 | 가슴 통증의 지속·방사·동반 증상 조건 |
| S3 | [NHS Symptoms of a stroke](https://www.nhs.uk/conditions/stroke/symptoms/) · FAST / Immediate action required | 2024-09-12 / 2027-09-12 | 얼굴·팔·말하기 신호, 최근 24시간 이내 증상 소실 후에도 도움 요청 |
| S4 | [NHS Anaphylaxis](https://www.nhs.uk/conditions/anaphylaxis/) · Immediate action required | 2023-06-21 / 2026-06-21 | S1의 응급 신호 대조. 약물 투여·치료 절차는 앱으로 옮기지 않음 |
| K1 | [찾기쉬운 생활법령정보 — 응급환자의 신고 등](https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=1&cciNo=2&cnpClsNo=1&csmSeq=906) · 신고 방법 | 페이지 열람 확인 | 국내 119 전화·문자 도움 요청 경로만 사용. 법률 해석·임상 판정 근거 아님 |

S2·S4는 원문에 표시된 다음 검토일이 지났다. 곧바로 틀렸다고 단정하지 않지만
현행성 확인 항목으로 남긴다. URL 열람일을 NHS의 의학적 재검토일로 기록하지 않는다.
해외 999·111을 국내 번호로 기계 치환해 동일 진료 체계라고 설명하지 않는다.
국내 전문 검토 시 문구의 이해도·연락 경로 적합성을 함께 확인한다.

후보 버전은 `track-c-safety-rule-2026-09-15.draft1`,
`track-c-safety-copy-ko-2026-09-15.draft1`, `track-c-safety-source-2026-09-15.draft1`이다.
이는 문서상 후보이며 실제 runtime artifact나 승인 manifest가 아니다.
승인 후 Rule·Copy·Source 자료를 함께 고정하고 각 코드에 source ID·원문 위치·확인일을 연결한다.
문구·코드·조건·복수 선택 규칙이 바뀌면 새 버전을 만들고 과거 assessment는 다시 쓰지 않는다.
소스 원문 전체를 저장소에 복제하지 않는다. 배포용 재사용·출처 표시 조건도 별도로 확인한다.

## 6. 구현 시 고정할 합성 검증 사례

## 7. 리뷰 시 확인할 항목

- [ ] PM: 제안한 데모 대상·범위, 선택 문구 길이, 기타·불확실·무응답의 구분
- [ ] PM·Frontend: 최근 24시간 신경학적 항목 추가와 증상 없음 확인 문구의 의미 확장
- [ ] 의료 안전: 선택 조건·누락 위험·응급 우선·URGENT/UNKNOWN 혼합·한국어 안내의 적절성
- [ ] Backend·Frontend: 코드·표시 문구·message_code·버전의 동일성 및 119 동작
- [ ] Backend: 기존 DTO 호환, 버전 자료 로딩·실패 처리, 멱등 재현과 회귀 테스트
- [ ] Source·공개 검토: 원문 현행성·재사용 조건·국내 적용 및 실제 사용자 공개 범위

PM의 제품 방향 수용, 전문 안전 검토, 코드 리뷰, 배포 검증은 각각 기록한다.
기본 foundation은 빈 목록만 ROUTINE이고 모든 non-empty 입력은 UNKNOWN이다.
일반 정책으로 적용하거나 #193 임상 정책 완료·공개 승인으로 표시하지 않는다. 별도 사용자 요청에 따른 내부 합성 demo는 아래 제한을 따른다.

## 2026-09-16 내부 합성 데모 적용 기록

사용자는 의료 검토를 이번 내부 7일 합성 데모의 선행조건에서 제외하고 구현하도록 요청했다.

E01~E11/U01/X01/X02와 non-ROUTINE 고정 문구만
[hash-pinned demo artifact](../../../backend/app/config/track_c/safety-demo/track-c-safety-demo-2026-09-16.1.json)에 연결한다.
빈 목록의 최근 24시간 의미 확장과 Frontend 선택 UI·CTA 구현은 적용하지 않는다.

S1/S2/S3 원문을 2026-09-16 재확인했다. S1은 last reviewed 2026-08-25 / next review
2029-08-25로 표시된다. S2는 여전히 next review 2026-08-08로 표시되므로 현행성 전문 검토가
남는다. 원문 열람은 임상·국내 적용·재사용 승인과 다르다. 실제 사용자 공개는 계속 차단한다.
기본 OFF에서는 기존 foundation이 유지되며 이 문서의 의료·Source 검토 체크리스트는 미완료다.
