## 문제와 사용자 의도

사용자는 식사 시간대·집중 업무 등 복용 곤란 시간·매일 반복 행동에 맞는 추천을 원한다. 약별 조건을 먼저 만족하고, 후보 이유와 필수 복용 조건을 구분한 뒤 고정 시각을 직접 확정하는 흐름이다.

첫 구현은 생활 입력을 저장하고 복원하는 것까지다. 저장 요청으로 약의 식사 조건을 판정하거나 시간 추천·기존 일정 변경을 실행하지 않는다. 식사 정보 없음과 식사 무관 약을 연결하지 않는다.

## 승인 전 확인

계약의 필드·enum·상한·route·새 오류 코드는 모두 제안이다. 식사 범위의 의미, 행동 종류, 요일·자정 UX는 남한솔과 협의한다. 송은영은 SELF profile 잠금과 공통 멱등성 scope/잠금 순서, 보존·삭제 및 권한 구현 경계를 확인한다. 권가빈은 최소 수집·초기화 안내와 목적별 동의 적용 필요성을 확인한다. 이 문서에서 동의 enum·의료 시간 간격·추천 알고리즘을 추가하지 않는다.

이슈 #556 착수 전에 위 결정을 정리한다. 구현 PR에는 확정된 계약·인덱스·migration·DTO/OpenAPI·코드·테스트를 정렬한다. Current 승격은 저장소 조건과 지정 리뷰를 충족하는 구현 PR에서만 처리한다. 이번 문서는 Proposed에 유지한다.

## 이번 검증 범위

문서·상대 링크·합성 JSON 예시·전체 diff·HTML 구조만 검사한다. 새 API/DB 구현이나 의료 평가 실행 결과는 없다. 후속 합성 HTTP/PostgreSQL 검증 항목은 정규 계약에 기록한다.

### 사용자 안내 문구 초안

입력 화면:

> 평소 식사 시간과 복용하기 어려운 시간, 반복되는 일과를 선택해 저장할 수 있어요. 시간 추천에 참고할 정보이며, 입력하지 않아도 기존 복약 일정과 기록을 사용할 수 있어요. 저장만으로 복약 일정이 바뀌지는 않아요.

초기화 확인:

> 저장한 생활 시간 설정을 비울까요? 기존 복약 일정과 기록은 유지돼요. 중복 저장을 안전하게 처리하기 위한 암호화된 응답 기록은 별도 보존·정리 기준에 따라 남을 수 있어요.

문구는 검토안이다. 현재 미구현 추천을 이용 가능한 기능처럼 안내하지 않도록 출시 단계에서 화면과 맞춘다. 초기화가 기존 동의 철회·계정 탈퇴까지 수행하는 것은 아니다.

### 남한솔 소비 협의안 — 답할 항목을 한정

권장 기본안은 다음과 같다. 실제 메시지 전송은 수행하지 않았으며 이 절은 공유 가능한 검토 자료다.

1. 기본 화면은 하루 패턴을 입력한 뒤 적용 요일을 선택해 복사. 서버에는 요일별 전체 패턴을 전송하고 저장 전 기존 다른 요일을 보존해 구성한다. 한 요일 편집이 다른 요일 삭제로 이어지면 안 된다.
2. 식사별 선택지는 `시간대 입력 / 불규칙 / 평소 먹지 않음 / 아직 입력 안 함`. 마지막은 해당 항목 생략. 식사 시각이 정확히 하나인 경우 현재 구간 DTO로는 표현되지 않으므로 임의 1분 구간으로 바꾸지 않는다. 한 시각 입력도 필요한지 확인 후 DTO 표현을 결정한다.
3. 대표 행동은 기상·외출·귀가·취침 4종을 초안으로 제안. 사용자가 말한 '출근 준비 완료'를 외출과 같은 의미로 자동 치환하지 않는다. 4종으로 충분한지 또는 준비 완료 같은 별도 종류가 필요한지 확인한다.
4. 자정 넘는 구간은 `23:00 → 다음 날 01:00`로 표시. 식사와 복용 곤란 시간이 겹쳐도 저장하고 오류로 막지 않는다.
5. 초기화는 별도 확인 후 전체 비우기, 동시 수정 409는 최신 값 재조회 후 사용자가 다시 편집하도록 안내. 입력을 조용히 덮어쓰지 않는다.

### 구현 착수와 실사용 적용의 구분

#556 구현 PR은 이 세부안의 리뷰와 병행해 합성 데이터용 구현안을 작성할 수 있다. 공유 계약은 Proposed로 표시하고 미합의 표현을 확정/공개 API로 주장하지 않는다. 코드 병합 전에는 실제 필요한 시각 표현·행동 종류와 책임 리뷰를 계약·DTO·테스트에 일치시킨다. 실제 사용자 대상 활성화는 안내·동의·보존/삭제 근거 확인 후 별도로 판단한다. 공개 차단의 배포 방식은 구현 PR에서 기존 환경 통제와 맞추며 미승인 flag/enum을 여기서 새로 만들지 않는다.

수집 범주를 다시 승인받는 단계는 없다. 남은 협의는 위의 구체적인 표현·처리안이며, 가빈님에게 '어떤 정보를 수집할지'를 다시 묻지 않는다.
