# PD-194-3 — 일정 변경·외출의 명시적 상황 선택

- 상태: 사용자 제품 방향 확정 / 구현·기술 리뷰 대상 / 공개 승인 아님.
- 구현 담당: 권가빈 (@hazelnutflavoured).
- 단일 책임 리뷰어: 김지혜 (@Jye-rookie), Backend·Frontend 소비 DTO·멱등성·설정 버전 검토.
- Frontend 영향: #139 / PR #629의 개발 전용 화면. 남한솔의 화면 소비 검토는 별도 증빙 대상이며 완료로 주장하지 않는다.
- 사용자 결정: 기존 ‘일정 변경·외출’ 안에서 생활 일정 변경과 약 미지참을 선택한다.

## 결정과 호환성

1. 생활 일정 변경은 기존 REMINDER_SETUP과 약 항목에 결속된 일정 확인·설정 화면을 사용한다.
2. 약 미지참은 ROUTINE_OR_TRAVEL_PLAN으로 다음 외출 전 약 챙기기 계획을 제안한다.
3. 화면 선택만으로 계획을 생성하지 않는다. 별도 채택으로 ACTIVE 계획을 생성하고 실제 준비 후 명시 완료한다.
4. Barrier enum·저장 테이블은 유지한다. GET query와 Plan 생성 body에 선택적 travel_situation을 추가한다.
5. 생략한 기존 소비자는 기존 priority 순 첫 1개 제안을 유지한다. 선택을 보낸 새 소비자는 해당 지원으로 후보를 제한한 뒤 기존 정렬·최대 1개 규칙을 따른다.
6. 과거 plan snapshot과 멱등 재시도를 보존한다. null/생략은 같은 기존 fingerprint로 취급한다.
7. 새 Rule·Copy 버전은 2026-09-16.1이며 과거 파일을 수정하지 않는다. 이번 문구는 약 챙기기 행동만 다루며 복용 시각·용량·놓친 약의 복용법을 결정하지 않는다.

이번 구현의 상세 경계는 [제안 계약](../../contracts/proposed/track-c-travel-situation-194.md)을 따른다.
다른 사유 기능의 확대와 알림 권한·Push 연결은 이 결정의 구현 완료 범위가 아니다.
기존 Safety·SELF·공개 gate를 유지하며 최종 책임 리뷰와 병합은 별도다.
