## 문제와 현재 기반

Notification 생성·앱 내부 게시·목록·읽음, 일정·Check-in, 정기 실행은 이미
develop에 있다. 외부 Push 채널은 없으며 `NotificationRecord.attempt=1`과
`delivered_at`은 앱 내부 게시를 의미한다. 이를 외부 전송 결과로 재사용할 수 없다.

현재 logout은 사용자 전체 `token_version`을 증가시킨다. 비밀번호 재설정과
refresh token 재사용 탐지도 같은 카운터를 증가시킨다. 회원탈퇴 API는
현재 계정 계약에서 후속 구현으로 남아 있다.

#469는 새 API·DB·오류·전송 정책의 합의를 요구하며 이슈 본문의 후보를 승인된
runtime 계약으로 취급하지 않는다. 아래 결정 후보에 대한 담당자 조율 증빙은
아직 없다. 2026-09-13 사용자가 계약안 기준 코드·테스트를 먼저 작성하고
계약 검토는 PR에서 받도록 명시했다. 이 지시는 책임 리뷰 승인이나 실기기
수신 검증을 대체하지 않는다.

## 검토할 결정

1. 표준 Web Push/VAPID와 `pywebpush`를 후보로 사용한다. 기존 Python 서비스에
   별도 구독 및 전달 ledger를 두고, Notification 행과 복약 상태는 재사용한다.
   Firebase·새 queue·AI Worker 변경은 필요하지 않다.
2. SELF profile 소유권과 등록 당시 `token_version`으로 구독을 결속한다.
   logout 이후 다른 기기도 다시 등록해야 한다. 계정 전환 시 기존 endpoint를
   다른 사용자에게 양도하지 않고 브라우저 unsubscribe 후 새 구독을 만든다.
3. 새 구독에는 등록 이전에 게시된 알림을 보내지 않는다. 서비스에 접수된 Push는
   회수할 수 없으므로 고정 일반 문구, 브라우저 구독 세대 확인, 클릭 후 인증된
   원본 알림 조회를 함께 적용한다.
4. `(notification_id, subscription_id, generation)`별 전달 ledger와 bounded
   retry를 사용한다. timeout·전송 중 crash는 결과 불명으로 종료하고 자동
   재전송하지 않는 안을 우선 검토한다. 수신 유실 가능성을 수용하는 제품 결정이다.
5. 기존 정기 실행의 앱 내부 게시 transaction과 별도로 외부 전송을 실행한다.
   외부 HTTP 동안 의료 row lock을 유지하지 않는다. 마지막 상태 검사 이후
   취소와 전송이 경합할 수 있다는 한계를 명시한다.

별도 테이블 두 개는 여러 기기·세대별 해제 및 전달 결과를 보존하기 위해 필요하다.
기존 Notification에 Push 필드를 추가하면 기기별 실패와 앱 내부 게시 의미가
섞인다. 별도 queue 대안은 현재 규모에서 불필요하다. 추가 비용은 migration,
구독 API, 암호화·SSRF 전송 경계, dispatcher 및 경합 테스트다.
