| 구현 담당 | 권가빈 (`hazelnutflavoured`) |
| 담당 리뷰 | 송은영 (`phina-io`): Backend/API·DB·Security; 남한솔 (`solia142`): Frontend 소비 계약 |

| 상위 승인 | [PD-417](./2026-09-10-track-b-schedule-contract.md), PR #424 |
| HTTP 계약 | [일정 API v1](../../contracts/proposed/track-b-schedule-api-v1.md) |

PD-417의 승인된 경로·입력·reason·revision·transaction 의미를 #438 저장 서비스와
#430 NotificationRepository에 연결한다. DB migration, 새 일정 생성 규칙, enum, 알림
상태나 정기 실행 배포를 추가하지 않는다. #202에 기록된 두 도메인 리뷰어가 아래 HTTP
구체화를 검토한다. 승인된 목표를 변경하는 새 정책을 이미 승인됐다고 표시하지 않는다.

HTTP의 생성·수정·취소 성공은 200 data envelope이며 operation은
`medication-schedule.put`, `medication-schedule.patch`, `medication-occurrences.list`다.
일정 write의 parent_resource_id는 version medication ID다. 없는 약과 다른 사용자 약은
기존 `PRESCRIPTION_MEDICATION_NOT_FOUND` 404로 숨긴다. 기존 일정 revision·활성 version
409와 공통 validation·멱등 오류를 재사용하며 새 오류 코드는 만들지 않는다.

조회 occurrence의 `scheduled_local_date`를 명시적으로 반환하여 #430 알림의
`occurrence_local_date`를 그대로 GET의 date에 전달할 수 있게 한다. 이는 알림 DTO 필드를
변경하는 작업이 아니다. 날짜별 현재 Check-in에는 기존 Check-in PUT data DTO를 재사용한다.
일정 변경 응답은 식별자·revision·상태·명시적으로 입력한 설정값을 반환하고 audit을 공개하지 않는다.

현재 PrescriptionVersionMedication snapshot에는 정확한 시작일·시각·반복 pattern 입력
필드가 없다. 일정 없음은 `MISSING_START_DATE`다. `timing_text` NLP, 처방일 대입, nullable
기간의 묵시적 OPEN_ENDED 처리나 가상의 정확한 입력 저장소를 추가하지 않는다. 나머지
승인 reason 값은 OpenAPI에 보존하지만 저장 근거가 없는 분기를 실행했다고 주장하지 않는다.
이후 정확한 입력 저장 계약이 생기면 PD-417의 전체 우선순위 실행을 연결해야 한다.

동일 키 재현 전 소유권을 확인한다. 신규 mutation은 기존 저장 서비스의 잠금·활성 version·
revision 검사를 거치고, 같은 세션의 실제 알림 취소와 암호화 응답 snapshot을 함께 저장한다.
순서가 다른 local_times는 정렬해 같은 지문으로 취급하고 중복 시각은 거부한다. snapshot cap
초과는 기존 SYNC_MUTATION savepoint에서 전체 rollback한다. 이 동작을 mutation 이전의
크기 예측으로 표현하지 않는다.

정기 실행 #434는 이 PR의 완료 주장이 아니다. 공통 Privacy 및 Track C/F 공개 gate는 유지한다.
